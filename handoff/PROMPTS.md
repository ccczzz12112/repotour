# 可直接粘贴给 Qoder 的提示词（按顺序用）

## 用前准备（一次性）

1. 打开 **Qoder CN** 客户端，用**已下单 Pro 的那个阿里云账号**登录。
2. 菜单「打开文件夹」，选择本仓库目录：
   `C:\Users\才\Documents\Codex\2026-11-21\w-ya\outputs\repotour`
3. 左侧栏点「**站点**」→「添加站点」，Qoder 会开一个新任务并自动引用 `@sites`。
4. 把下面 **P0** 整段粘进输入框发送。之后每一阶段用同一段会话继续，别开新任务。

> **每做完一步就截图**（任务对话 + 站点预览 + 发布成功页）。
> 官方评分单列「Qoder 使用深度」，作品帖必须附过程截图，事后补不出来。
> 建议截图统一存到 `handoff/evidence/`，命名 `P0-01-建站.png` 这样。

> **安全**：`.env` 里有密钥配置项，永远不要把真实 Key 写进站点前端代码或提交到 Git。
> 站点版的模型能力走 Qoder 自带的 Cloud Agents，不需要你自己的 API Key。

## P1 · 种子数据 + 导览路线 + 代码证据（核心卖点）

```
继续。现在把导览功能做出来，数据先用预烘焙种子，保证点开即用、不依赖网络。

种子数据在 handoff/seed/ 下三个文件：pallets-click.json、psf-requests.json、axios-axios.json。
每个文件结构是 { meta, result, files }，result 的字段含义见 handoff/SPEC.md 第 3 节，
files 是「文件路径 -> 文件全文」的字典，用来离线渲染代码。

要求：
1. 首页三个示例按钮接上真实种子数据，点击后 2 秒内进入导览页。
2. 导览页三栏：左栏站点列表（result.tour 按 order 排序，显示序号和标题）、
   中栏当前站讲解卡片（title / why / narrative / quiz）、
   右栏代码面板。
3. 讲解里的 result.tour[].files 每条渲染成可点击的引用胶囊，显示「path:start-end」。
   点击后右栏从 files[path] 取全文，显示真实行号，并高亮 start..end 行。
   行号必须是文件里的真实行号，不能从 1 重新数。
4. 上一站/下一站按钮，支持键盘左右方向键切换，左栏当前站高亮，顶部显示「第 3 / 10 站」。
5. 页头徽章显示 result.stats.evidence_passed / evidence_total，
   文案「引用验证 40/40」，鼠标悬停解释「每条讲解都绑定了真实代码行号并程序校验通过」。
6. 代码面板支持复制、折叠、按语言语法高亮。

注意：种子里的 narrative 文案目前是规则拼的占位内容，这一轮先照原样渲染，
文案重写放到后面单独一轮做。结构和行号是真实的，不要改。

做完生成预览，我要逐个点开 10 个站点和代码引用检查。
```

**验收**：三个示例都能点；10 站都能切；随便点一条引用，右栏高亮的代码和 GitHub 上该文件对应行一致。

## P2 · 架构图 + 模块地图 + 上手任务

```
继续。补齐另外三个页签，数据同样来自种子的 result。

架构图页：
- 用 result.graph 画分层有向图，nodes[].layer 决定分层（同层横向排开），避免连线交叉。
- edges[].verified 为 true 画实线，false 画虚线并标「未验证」。
- 悬停节点时高亮它的所有邻边和相邻节点，其余淡出。
- 点节点弹出详情：label、note、包含的 paths 列表，点 path 能跳到代码面板。
- 图上方写一句说明：「所有依赖边来自真实 import 静态解析，不是模型推测」——这是我们的核心卖点。
- 支持缩放、拖拽、一键回到全览。

模块地图页：
- result.modules 按 importance 降序排成卡片。
- 每张卡显示 path、role 徽章（entry/core/util/model/api/config/test/doc 用不同颜色）、
  responsibility、key_symbols 标签、importance 条。
- 支持按 role 筛选和按路径搜索。
- 点卡片跳代码面板，定位到它的 evidence 第一条。

上手任务页：
- result.tasks 按 level 1/2/3 分成三档卡片，标注难度。
- 显示 description、涉及文件（可点跳代码）、acceptance 验收标准。
- hints 默认折叠，点「看提示」逐条展开。
- 每张卡有个「我完成了」勾选框，状态存 localStorage，刷新后保留，顶部显示完成进度。

三个页签都要适配手机宽度，不出现横向滚动。做完生成预览。
```

**验收**：架构图的每条边，能在源文件里找到对应的 import 语句；任务打卡刷新后还在。

## P3 · 用模型重写讲解文案（把占位文案换成人话）

```
继续。现在解决文案质量问题。

种子数据里的 tour[].narrative、modules[].responsibility、graph.nodes[].note
目前是规则拼出来的占位内容，直接截了 README 原文和 docstring 片段，读起来不像人话。
比如 pallets-click.json 第 0 站的 narrative 直接是 README 的英文原文，
psf-requests.json 第 3 站是 docstring 的下划线标题行。这些都要重写。

请用你的模型能力，基于每个站点对应的真实代码内容（种子的 files 字典里有全文），
重写三个种子文件里的讲解文案，要求：

1. 全部中文，写给「刚接手这个仓库、还没读过一行代码的大学生」看。
2. tour[].narrative 每站 150-300 字，必须讲清楚三件事：
   这个文件在整条调用链里处于什么位置、它解决什么问题、读的时候重点看哪几个符号。
   不要复述代码，不要空话，要具体到函数名和类名。
3. tour[].why 一句话说明「为什么第 N 站读这里而不是别处」，要体现认知递进。
4. tour[].quiz 一个能检验是否真读懂的具体问题，不要「你理解了吗」这种。
5. modules[].responsibility 一句话，不超过 40 字，说清职责。
6. graph.nodes[].note 一句话说明这一层干什么。
7. tasks 的 description / acceptance / hints 也重写成可操作的中文。

严格约束（这是产品卖点，不能破坏）：
- 不许修改任何 files 字段里的 {path, start, end}，行号是校验过的真实数据。
- 不许新增或删除 tour 站点、不许改 order。
- 不许新增 graph.edges，架构边只能来自真实 import 分析。
- 重写后每条讲解提到的函数名/类名，必须真的出现在它引用的代码行范围附近。

重写结果直接更新 handoff/seed/ 下的三个 json，并同步到站点数据。
做完告诉我改了哪些字段，我要抽查文案和代码是否对得上。
```

**验收**：随便挑 3 站读一遍，讲解里提到的符号能在高亮代码里找到；没有英文 README 原文残留。

## P4 · 在线生成（输入任意仓库链接）

```
继续。现在开放首页输入框，支持分析任意 GitHub 公开仓库。

算法规格在 handoff/SPEC.md 第 4 节，请严格照它实现，全部在浏览器端完成，不要自建服务器。

取数据：
- GET https://api.github.com/repos/{owner}/{repo} 拿 default_branch
- GET https://api.github.com/repos/{owner}/{repo}/git/trees/{branch}?recursive=1 拿全量文件树
- 文件内容走 https://raw.githubusercontent.com/{owner}/{repo}/{branch}/{path}
  （这个域名支持跨域且不占 API 限额，千万不要用 contents API 逐个拉，会撞 60 次/小时限流）
  备用源 https://cdn.jsdelivr.net/gh/{owner}/{repo}@{branch}/{path}
- 只拉排序后的 top 60 个文件，并发 6-8 个，单文件超过 200KB 跳过。

浏览器端依次做：
1. scan：静态扫描 + import 依赖解析（Python 和 JS/TS 正则见 SPEC 4.2），产出真实依赖边
2. rank：PageRank-lite 12 轮 + 入口加成 3 倍 + 规模因子，取 top 60（见 SPEC 4.3）
3. map/reduce/tour/tasks：这四步交给模型，产出结构与种子完全一致的 result
4. evidence：逐条校验 {path,start,end} 落在真实文件行数范围内，
   不通过的引用从 UI 移除并计入 stats（见 SPEC 4.5）

交互：
- 提交后显示 7 步进度时间线：取文件 → 静态扫描 → 关键文件排序 → 模块讲解 → 架构聚合 → 导览路线 → 上手任务，
  每步有进行中/完成状态和简短说明，让用户知道在干什么。
- 生成完成后自动进导览页，页头徽章显示真实的校验通过率。
- 结果存 localStorage，首页显示「最近生成」列表，可重新打开。
- 失败要有明确中文提示：仓库不存在 / 私有仓库无权限 / 触发限流请稍后或填自己的 token /
  仓库太大 / 网络错误，每种都给下一步建议，不要只显示「失败」。
- 可选设置项：让用户粘贴自己的 GitHub Personal Access Token 提高限额，
  只存 localStorage，绝不上传到任何服务器，界面上要写清楚这一点。

模型调用走站点的后端能力或 Cloud Agents，前端代码里不能出现任何 API Key。
做完先在预览里完整跑通一个没预烘焙过的仓库（比如 https://github.com/pallets/flask），确认后再发布。
```

**验收**：输入一个全新仓库能成功出结果；断网时三个示例仍完整可用；错误提示能看懂。

## P5 · 打磨与盲测修复

```
继续。最后一轮打磨，目标是「评委不看说明书就能用起来」。

1. 首屏：3 秒内让人看懂这是什么。检查标题、副标题、示例按钮是否够显眼，
   加一张示意图或动图说明「输入链接 → 得到路线」，不要让人先读一段文字。
2. 三态文案全部补齐：加载中（骨架屏 + 当前在做什么）、空状态（引导点示例）、
   错误态（原因 + 下一步怎么办）。所有文案中文、说人话。
3. 移动端：手机宽度下三栏改成上下堆叠或抽屉，代码面板可全屏，
   所有可点区域不小于 44px，不出现横向滚动。
4. 键盘可达性：左右方向键切站点，Esc 关弹窗，Tab 顺序合理，焦点可见。
5. 首次访问给一个 3 步极简引导（点示例 → 读站点 → 点引用看代码），可关闭且不再打扰。
6. 加一个「关于」入口，写清楚三个差异化设计：输出路线不是文档、
   每条结论绑定可校验代码证据、架构边只来自静态分析。
7. 检查所有外链、按钮、页签，不能有死链和点了没反应的地方。

改完发布，并确认访问范围仍是「任何人都可访问」。
我会找没参与项目的同学盲测，把问题反馈给你继续修。
```

**验收**：找一个没参与项目的同学，不给任何说明，能独立走完「打开 → 点示例 → 读站点 → 点引用看代码」。
