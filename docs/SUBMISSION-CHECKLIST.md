## 5. 技术缺口：现有架构上不了 Sites

Qoder Sites 不是通用服务器托管，它是 Qoder 自家的站点服务，能力边界：

- 静态页面（Free 版即可）
- Server Functions + 数据库 + 对象存储（Pro，即 Agent App）
- 可调用 Qoder Cloud Agents 跑模型任务（**不用自己买 API Key**）
- Qoder CLI 支持「从现有项目构建网站」，例如「帮我把 dist 发布成站点」

我们的 **Python FastAPI + 本地 git clone + SQLite** 跑不上去。必须改造。

### 推荐路线：RepoTour 浏览器版

把后端逻辑搬到浏览器 + Server Function，天然适配 Sites，还顺手解决了 API Key 问题：

| 现有步骤 | 搬到哪 | 说明 |
|---|---|---|
| fetch（git clone） | 浏览器 `fetch` GitHub REST API | 公开仓库免 token 可读；带 token 提额度 |
| scan（import 静态分析） | 浏览器 TS | 逻辑照搬 `scan.py`，Qoder 翻译 |
| rank（关键文件排序） | 浏览器 TS | 照搬 `rank.py` |
| map / reduce / tour / tasks | Sites Server Function 或 Cloud Agents | 模型由 Qoder 提供，**无需自备 Key** |
| evidence 校验 | 浏览器 TS | 文件内容已在手，`{path,start,end}` 当场校验 |
| preview 静态导出 | 保留 | 做 3–5 个示例仓库的预烘焙，兜底防断网 |

**保底策略**：先把 3–5 个热门仓库的导览结果预烘焙成静态 JSON 随站点发布，
评委点开立刻能看能玩；再叠加「输入自己的仓库 URL 在线生成」。
即使在线生成挂了，站点依然完整可用。

### 功能层面的既有缺口

- [ ] `LLM_MODE=mock` —— 目前导览文案是规则拼的，不是真模型输出（走 Cloud Agents 后此项自然解决）
- [ ] 3–5 个示例仓库预烘焙数据
- [ ] 前端打磨：移动端适配、上一站/下一站 + 键盘快捷键、架构图邻边高亮、任务打卡、首屏示意图
- [ ] 空状态 / 错误态 / 加载态文案（评委第一次打开看到的东西）
- [ ] `POST /api/jobs/{id}/ask` 带引用问答 —— **建议直接砍掉**，不计分
