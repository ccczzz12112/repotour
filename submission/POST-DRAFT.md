## 二、你的作品是什么

**一句话**：给刚接手陌生代码仓库的学生和新人，把「从哪读起」变成一条能点着走的导览路线。

**作品链接（Qoder Sites 公开访问）**：【填 P0 拿到的链接】

输入一个 GitHub 仓库链接，RepoTour 会产出：

1. **6–10 站有序导览路线** —— 按新人第一天的认知顺序排，不是平铺文档
2. **架构图** —— 分层模块图，每条依赖边都来自真实 import 静态解析
3. **模块地图** —— 每个关键文件的职责、核心符号、重要度与「为什么它重要」
4. **分级上手任务** —— 三档难度，带验收标准和提示，读完就能动手

**三个和别人不一样的地方**：

- **输出路线，不是文档**：解决的是「从哪读起」，不是「这个函数什么参数」
- **每条结论都绑定可校验的代码证据**：任何讲解都附 `{文件路径, 起始行, 结束行}`，
  程序逐条校验行号真实存在，页面显著展示「引用验证 40/40 通过」，点一下就能看高亮源码
- **架构边只来自静态分析**：模型只负责讲解，不许编造结构，从根上压制幻觉

## 三、为什么做

【用真实经历写，2–3 段。参考素材：】

做课程项目 / 参加开源 / 看论文配套代码时，clone 下来面对几百个文件，
README 只讲怎么安装，不讲怎么读。想知道「主流程从哪进、核心逻辑在哪」，
只能靠全局搜索加瞎猜，两小时过去了还没读懂一个文件。

现有工具要么生成一堆平铺文档（还是不知道从哪读起），
要么直接让大模型总结（说得头头是道，但引用的函数根本不存在）。

我们想要的是：**一条有顺序的路线 + 每句话都能点回真实代码验证**。

## 四、怎么用（5 步以内）

1. 打开链接：【作品链接】
2. 首页点任一示例仓库（推荐 `pallets/click`）
3. 进入导览路线，从第 1 站开始读，用「下一站」或键盘 ← → 前进
4. 点讲解里的代码引用胶囊，右侧立刻显示高亮源码，核对讲解是否属实
5. 切到「架构图 / 模块地图 / 上手任务」页签，挑一个任务动手

进阶：首页输入框粘贴任意 GitHub 公开仓库链接，等进度条走完即可。
