## 0. 一句话定位

**丢进任意 GitHub 仓库链接，AI 生成一条可交互的"新人导览路线"：
架构总览 → 模块讲解 → 沿着一条真实调用链读源码 → 分级上手任务。
每一句结论都能点击跳回源码行号。**

- 目标用户：接手陌生代码的学生（课设/科研/实习）、开源新手、入职新人。
- 核心痛点：README 只讲"这是什么"，不讲"该怎么读"；现有工具生成的是"另一篇长文档"，阅读负担没有变小。
- 产品隐喻：不是给你一本说明书，而是派一个导游带你走一遍。

## 1. 三个灵魂设计（差异化，答辩时反复强调）

### 1.1 路线，不是文档
输出是 6–10 个有序的"导览站点"（Tour Stops），按新人第一天的认知路径排序：
入口在哪 → 跟一个真实请求/命令走一遍 → 核心模块 → 数据层 → 测试怎么写。
每站有：讲解（≤150字）、为什么重要、源码片段（高亮行）、一个理解自测问题。
有"下一站"按钮和进度条（导览进度 3/8）——像游戏新手引导，不像 wiki。

### 1.2 每句话都有证据（Evidence-grounded）
LLM 的每条结论必须附带 {文件路径, 起止行号}。
- 程序化校验：路径必须真实存在、行号在文件范围内、（增强）引用的符号名能在该文件中 grep 到。
- 校验失败的结论直接丢弃或标记"推测"。
- 前端所有引用可点击 → 右侧代码查看器跳转并高亮。
这是对"LLM 读代码全靠编"的正面回击，是最硬的技术分。

### 1.3 静态分析搭骨架，LLM 长血肉（Hybrid Grounding）
- 依赖图的"边"来自真实 import/require 解析（Python 用 ast，JS/TS 用 import 正则或 tree-sitter），不是 LLM 想象。
- LLM 只负责：给节点起名字、分层、写讲解、规划路线。
- LLM 提出但静态图中不存在的边 → 标记为 inferred 或丢弃。
一句话话术："架构图里每条线都经得起点击查看。"

## 2. 功能分级（砍线明确，防止 scope 失控）

| 级别 | 功能 | 说明 |
|---|---|---|
| P0 灵魂 | 仓库克隆+扫描、import 依赖图、模块摘要、架构图交互渲染、导览路线+三栏联动 UI、证据点击跳转 | 少一个都不算完成 |
| P1 加分 | 分级上手任务清单（3–5个，含验收标准）、"问这个模块"带引用问答、分析进度流式展示 | 时间够就上 |
| P2 只写进 roadmap | 沙箱执行验证任务、多语言全覆盖、私有仓库、增量更新、PR 级导览 | 答辩提一句，绝不动手 |

语言范围：**首版只支持 Python + JS/TS**，仓库规模限制 ≤2000 文件 / ≤50MB（超限给出友好提示）。

## 3. 核心流水线（7 步，Agent Pipeline）

    URL → ① Fetch → ② Scan → ③ Rank → ④ Map(LLM) → ⑤ Reduce(LLM) → ⑥ Tour(LLM) → ⑦ Tasks(LLM)
                每一步产物落盘 JSON，可断点续跑，前端 SSE 实时展示每步状态

1. **Fetch**：git clone --depth 1；排除 node_modules/vendor/dist/.git 等；记录 commit hash（结果可复现）。
2. **Scan（纯确定性，不用 LLM）**：文件树、语言统计、入口探测（main.py / manage.py / package.json 的 main·bin·scripts / pyproject.toml）、测试目录、CI 配置、README。
3. **Rank**：按 import 图中心度 + 是否入口 + 文件规模，选出 top ~150 个"值得读的文件"。这是控制 token 成本的关键。
4. **Map（LLM 第一遍，自底向上）**：对选中文件逐个生成模块卡片 {职责, 关键符号, 角色, 读写的数据, 证据行号}；再按目录聚合出子系统摘要。并发调用 + 缓存（按文件 hash）。
5. **Reduce（LLM 第二遍）**：输入全部模块卡片 + 已验证的依赖边 + README 摘录 → 输出架构 JSON：分层（入口/业务/数据/外部）、节点分组、每条边的解释。边校验见 1.3。
6. **Tour（LLM 第三遍）**：从入口沿依赖图选一条真实调用链，生成 6–10 个站点；每站绑定文件+行段+讲解+自测问题。行段做程序化校验。
7. **Tasks（LLM 第四遍）**：3–5 个分级任务：L1 观察型（"找到 X 在哪注册"）→ L2 理解型（"画出 Y 的调用顺序"）→ L3 微型修改（含验收标准：跑通哪条现有测试）。每个任务附提示（可折叠）和涉及文件。

## 4. 可靠性与工程设计（评委眼中的"完成度"）

- **证据校验器**：独立模块 validate(evidence) → 路径存在 / 行号合法 / 符号可寻。统计"引用验证通过率"显示在结果页（例如 47/49 条引用已验证）——把可靠性变成可见的指标。
- **缓存与断点续跑**：job 产物按步骤存 SQLite + 文件系统；同 repo+commit 直接秒开（演示用预烘焙仓库就靠它）。
- **失败兜底**：超大仓库/不支持语言/克隆失败 → 明确报错文案；LLM 输出 JSON 解析失败 → 自动重试一次 + 修复提示。
- **成本控制**：Rank 截断 + 文件摘要缓存 + 便宜模型跑 Map、强模型只跑 Reduce/Tour。中等仓库全流程目标 < 5 分钟、< ¥5。

## 5. 技术栈与架构（按 1–3 人学生队、无 GPU 假设）

- 前端：**React + Vite + TypeScript + Tailwind**；架构图 **React Flow**（点击节点→跳代码）；代码查看 **CodeMirror 6**（行高亮）；进度用 SSE。
- 后端：**Python FastAPI**（ast 解析 Python import 零成本；JS/TS 用 import/require 正则起步，tree-sitter 可选升级）；后台任务用 FastAPI BackgroundTasks / arq；存储 SQLite + 文件缓存。
- LLM：任意 OpenAI 兼容 API（Qwen / DeepSeek 均可），Map 用便宜快模型，Reduce/Tour 用强模型。**不需要 GPU**。
  - 若队里有 JS 全栈没 Python：后端换 Node + Express，Python import 解析改为正则，架构不变。
- 问答（P1）：按函数/类分块 + BM25（rank_bm25）检索即可，不必上向量库；回答强制带引用。

    [React SPA] ──REST/SSE── [FastAPI]
                                ├─ Pipeline（7步，产物JSON落盘）
                                ├─ Static Analyzer（ast/regex → import图）
                                ├─ Evidence Validator
                                ├─ LLM Client（分级模型+重试+缓存）
                                └─ SQLite + repo缓存

## 6. 数据模型 & API 草案

    Job      {id, repo_url, commit, status, current_step, created_at}
    Module   {id, path, kind, summary, key_symbols, importance, evidence[]}
    Graph    {nodes:[{id,label,type,layer,module_ids}], edges:[{src,dst,kind,verified,note}]}
    TourStop {order, title, narrative, why, files:[{path,start,end}], quiz}
    Task     {level, title, description, files[], acceptance, hints[]}
    Evidence {path, start, end, symbol?}

    POST /api/jobs                {repo_url} → {job_id}
    GET  /api/jobs/{id}/events    SSE：每步进度/日志
    GET  /api/jobs/{id}/result    → {overview, graph, tour, tasks, stats}
    GET  /api/jobs/{id}/file      ?path=&start=&end= → 代码片段
    POST /api/jobs/{id}/ask       {question, stop_id?} → {answer, citations[]}   (P1)

## 7. UI 设计（三个页面，别多做）

1. **首页**：一个 URL 输入框 + 3 个预烘焙示例仓库卡片（点开秒出结果）+ 分析中显示 7 步流水线时间线（让评委看见 Agent 在干活）。
2. **导览页（主战场，三栏联动）**：
   - 顶部：可交互架构图，当前站点对应节点呼吸灯高亮；
   - 左栏：站点列表（路线 + 进度）；
   - 中栏：讲解卡片（叙述 / 为什么重要 / 可点击证据 / 自测问题）；
   - 右栏：代码查看器，自动跳转并高亮引用行段。
   - 底部："下一站 →"。
3. **任务页**：分级任务卡（L1/L2/L3），验收标准 + 可折叠提示 + 涉及文件跳转。

## 8. LLM Prompt 要点（四段式，全部要求 JSON 输出）

- Map："你是代码考古学家。给定文件内容及其 import 关系，输出 {responsibility, key_symbols, role, data_touched, evidence[]}。每条结论必须给行号，禁止编造不存在的符号。"
- Reduce："给定模块卡片与【已验证】的依赖边，输出分层架构 JSON。只能使用给定的边；如需补充关系，标记 inferred 并说明依据。"
- Tour："按'新人第一天的认知路径'规划 6–10 站，从入口沿真实调用链前进。每站 ≤150 字讲解 + why + 文件行段 + 一个理解问题。行段必须来自给定文件。"
- Tasks："生成 3–5 个由观察到微改的任务，L3 任务必须给出现有测试作为验收方式，不得要求新增基础设施。"
- 通用：温度调低；JSON schema 校验失败自动重试；所有 evidence 过校验器。
